- 官方固定 commit 的 raw / zlib 测试向量通过。发送单块字节与上游逐字节一致，向量同时由官方 decoder 验证；损坏数据与解压输出超限会被拒绝。
- APK 内容检查确认 ZXing LICENSE / NOTICE 已打包，位于 main assets，正常版与精简版共用。

尚未完成两台真机对扫与功耗实测。摄像头对焦、不同分辨率/亮度、真实锁屏和厂商权限行为仍需真机验收。模拟器上的图像识别与界面通过不代表这些条件已验证。

## 可调帧率与分块大小

发送页新增参数弹窗，以滑块调节目标帧率 1–60 Hz、分块大小 100–1500 字节，默认 10 Hz / 500 字节。点击应用后生效，参数跨旋转保留；改变分块会重新编码，并提示接收端重新开始接收。生成耗时计入帧周期，实际帧率仍受设备性能限制。

- `:app:lintDebug`、`:app:assembleDebug`、`:app:assembleDebugAndroidTest` 通过。
- QRS JVM 8 项通过：新增 100、137、500、1499、1500 字节的漏帧恢复、非法大小拒绝，以及改变分块后旧接收状态拒绝混入数据。
- QRS 设备 3 项通过：图像链路分别覆盖 1500 字节加密备份、100 字节无密码备份；滑块设置 37 Hz / 137 字节并应用，旋转后保持参数；密码重试、过期相机结果等回归通过。
- 高帧率真机对扫吞吐量与功耗尚未测量。

## 实时滑块

后续调整为直接在发送页显示滑块，拖动即时更新，无弹窗和应用按钮。暂停时改变分块也刷新静态二维码。修改帧率保留接收进度；新版接收器在同一 CRC32 / 编码长度下识别块宽变化，清空旧方程继续接收，不混用不同宽度的数据；其他备份仍拒绝混入。原有接收端需要更新才能自动适配分块改变。

- 构建、Lint、8 项 QRS JVM 测试、3 项 QRS 设备测试通过。
- JVM 测试连续切换 100→137→1500→1499→500→100 字节，用同一个接收器完成解码，并验证另一份数据即使块宽改变仍被拒绝。
- 设备测试不再点击应用按钮，直接改变两个滑块后验证模型及旋转后的数值。1280×800 / 160 dpi 横屏平板额外复测 1 项通过。
- 两台真机边扫边调的表现及功耗尚未实测。
