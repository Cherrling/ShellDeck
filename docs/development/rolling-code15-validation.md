# Rolling code 15：SFTP 目录导航

## 修改

- 每个 SSH 会话的文件浏览器惰性创建并复用一个 SFTP 通道；退出文件页/旋转不关闭，结束 SSH 会话时关闭。普通读取失败后丢弃通道，下次用户导航重建，不新增 SSH 自动重连。
- 浏览和传输使用独立执行器、通道、进度与取消状态；上传下载期间仍可浏览目录。读取本地待上传文件元数据不创建网络通道。
- 列表中已知的普通目录直接读取，省去一次 stat 和一次 realpath；首次访问、手动路径、符号链接继续解析。文件下载前保留类型检查，避免将特殊文件当普通文件。
- 主线程 LRU 缓存最多 16 个目录、合计 20,000 个条目，只保存在会话内存中。命中立即显示，随后异步刷新；失败时明确提示显示缓存。无定时刷新或磁盘缓存。
- 一次运行中的导航加一个最新待执行导航；新请求替换排队的旧请求，递增编号确保旧结果不覆盖当前页面。
- 文件变更后清除缓存并刷新当前/正在前往的目录，不跳回上传目标。目录取消只关闭浏览通道；传输取消只关闭传输通道。

## 验证

- JVM：目录缓存数量/总条目限额和 LRU 淘汰；真实 SFTP 上传下载、默认不覆盖、原子覆盖、符号链接删除与取消。
- Android 15 模拟器：SftpNavigationDeviceTest 对真实 SFTP 目录读取注入 120ms 延迟，并用同步闸门稳定复现旧导航与新导航交错、传输中浏览和取消。验证普通目录不重复 stat/realpath、多个目录只创建一个浏览通道、缓存立即显示、最后请求生效、传输取消保留浏览通道、浏览取消后按需重建。
- SftpDeviceTest：文件选择器、上传下载、Activity 重建、同名拒绝覆盖保留原内容。
- BackgroundServiceDeviceTest：服务继续持有连接、通知划除不补发、界面退出与恢复。
- 不把上述注入延迟当作真实移动网络测速；尚未测量用户服务器上的改善倍数。首次读取大目录仍需要远端返回全部条目。

验证结果：上述 3 项设备测试全部通过、无跳过；保留文件类型检查后的 2 项 SFTP 设备用例再次通过。目录缓存与真实 SFTP 的 JVM 用例通过，debug/release 编译及 lint 通过，Termux 完整性校验通过。正式 APK 已验证包名 cc.cherr.shelldeck、版本 0.1.0 (15) 及既有签名证书。
